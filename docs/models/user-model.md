# User Model Design

## Purpose
Represents users who create, update, assign, or review tickets.

## Core Fields
- `_id`: MongoDB ObjectId
- `name`: required, trimmed string
- `email`: required, unique, normalized to lowercase and trimmed, with email-format validation
- `password`: required bcrypt hash; excluded from normal queries and removed from JSON serialization
- `role`: required enum (`ADMIN`, `DEVELOPER`, or `VIEWER`)
- `createdAt`, `updatedAt`: timestamps generated by Mongoose

## Role Values
- `ADMIN`
- `DEVELOPER`
- `VIEWER`

All new registrations create `VIEWER` users. Administrators can change user
roles through the protected user-management APIs. Only administrators can use
the user-management routes. An administrator cannot change their own role, and
the last administrator cannot be demoted.

## Schema Intent
The user model supports:
- ticket creation and assignment references
- role-based access control
- administrative user lists and reporting

## Relationships
- A user can be referenced by tickets through `createdBy`.
- A user can be referenced as a ticket `assignee`.
- Comment relationships are not part of the current model.

## Design Notes
The current schema does not define `avatarUrl`, `isActive`, team/department, or permission-list fields. Role permissions are enforced by backend route middleware rather than being stored per user.
