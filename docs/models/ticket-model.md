# Ticket Model Design

## Purpose
Represents a work item persisted by the current Mongoose ticket schema.

## Core Fields
- `_id`: MongoDB ObjectId
- `title`: required string, trimmed
- `description`: required string, trimmed
- `priority`: optional enum
- `status`: optional enum
- `category`: optional string, trimmed; no fixed category enum is enforced by the schema
- `assignee`: optional reference to a User
- `createdBy`: optional reference to a User, set by the create-ticket controller
- `createdAt`, `updatedAt`: timestamps generated by Mongoose

## Status Values
- `NEW`
- `IN_PROGRESS`
- `RESOLVED`
- `CLOSED`

## Priority Values
- `LOW`
- `MEDIUM`
- `HIGH`
- `CRITICAL`

## Category Values

Ticket categories are stored as strings and are not restricted to a fixed set by the ticket schema. The AI analysis service recommends one of `UI`, `Backend`, `Infrastructure`, `Database`, `Security`, or `Other`.

## Relationships
- `assignee` references a user when assigned.
- `createdBy` references the user who created the ticket.
- Comments and a separate persisted AI-analysis record are not fields or relationships in the current ticket schema.

## Design Notes
The Angular ticket dialog requires title, description, priority, and status; priority and status are optional in the Mongoose schema and can be omitted by direct API clients. AI analysis is returned to the UI for review; it does not itself update or save the ticket.
